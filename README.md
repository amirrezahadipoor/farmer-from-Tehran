## اجرا

```bash
npm install
npm run dev          # http://localhost:3000
```

برای کلونِ سبک (حدودِ ۱۱ مگابایت، بدونِ تاریخچه‌ی قدیمیِ اسکرین‌شات‌ها): `git clone --depth 1 https://github.com/amirrezahadipoor/farmer-from-Tehran.git`

### انتشار

| نسخه | چطور | ویژگی |
|---|---|---|
| دموی عمومی | خودکار با هر push به main (`.github/workflows/pages.yml`)؛ بعد از انتشار تستِ دود روی همان آدرس اجرا می‌شود | ایستا روی GitHub Pages، بدونِ API؛ ذخیره روی دستگاه |
| نسخه‌ی کامل | [![Deploy with Vercel](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2Famirrezahadipoor%2Ffarmer-from-Tehran) یا `npm run build && npm start` روی هر سرورِ Node | همگام‌سازیِ ابری وقتی `DATABASE_URL` تنظیم شود |

**بدون هیچ متغیر محیطی اجرا می‌شود.** پایگاه‌داده اختیاری است:

```bash
cp .env.example .env    # اگر همگام‌سازی ابری می‌خواهی
npm run db:push         # ساخت جدول farm_saves
```

### پایگاه‌داده اختیاری است (lazy DB)

اتصال به Postgres **تنبل** ساخته می‌شود: `getDb()` تا وقتی `DATABASE_URL` نباشد
هیچ استخری باز نمی‌کند و `null` برمی‌گرداند. نتیجه‌ی عملی:

| بدون `DATABASE_URL` | رفتار |
|---|---|
| `npm run build` | موفق — هیچ متغیری لازم نیست (در CI هم همین تست می‌شود) |
| `GET /api/save` | `{ data: null, mode: "offline" }` — بازی از سیوِ روی دستگاه ادامه می‌دهد |
| `POST /api/save` | `{ ok: false, mode: "offline" }` — کلاینت ذخیره را در «صندوق خروجی» می‌گذارد |
| `GET /api/health` | `{ ok: true, database: "offline", configured: false }` |

با داشتن دیتابیس: `cp .env.example .env` و تمام. جدول `farm_saves` و ستون‌هایش در اولین
درخواست خودکار (و idempotent) ساخته می‌شوند؛ `npm run db:push` هم همچنان کار می‌کند.
سرور خودکار ابری می‌شود و سیوهای در صف، هنگام برگشت اینترنت ارسال می‌شوند.
شاهد خودکار: `tests/api.test.ts` همین رفتار را بدون دیتابیس تست می‌کند.

### امنیتِ سیوِ ابری (P5.13)

| قاعده | پیاده‌سازی |
|---|---|
| سیوِ هر بازیکن فقط با توکنِ خودش | هر دستگاه یک توکنِ تصادفیِ ۲۵۶ بیتی دارد (`farm_token`) که با سرآیندِ `x-farm-token` می‌رود. اولین نوشتن مالکیت را ثبت می‌کند؛ بعد از آن توکنِ دیگر نه می‌خواند نه می‌نویسد (`403`). بی‌توکن `401` است. مالکیت در خودِ نوشتن اتمی بررسی می‌شود (یک upsertِ شرطی)، پس دو نوشتنِ اولِ هم‌زمان یک مالک دارند |
| توکن هیچ‌جا ذخیره نمی‌شود | سرور فقط sha256 توکن را در ستونِ `token_hash` نگه می‌دارد و مقایسه را در زمانِ ثابت انجام می‌دهد |
| سقفِ حجم | بدنه‌ی بیش از ۵۱۲ کیلوبایت `413` می‌گیرد. هم `content-length` بررسی می‌شود و هم شمارشِ واقعیِ جریان. یک سیوِ واقعی حدود ۵۹ کیلوبایت است |
| سقفِ نرخ | هر «شناسه + IP» ۸ نوشتنِ پشتِ‌سرِهم می‌تواند و بعد هر ۴ ثانیه یکی. هر IP هم در ثانیه یک درخواست دارد با ذخیره‌ی ۶۰ تایی. بیشتر از این `429` با `Retry-After` است. IP از تهِ `X-Forwarded-For` خوانده می‌شود (به تعدادِ پراکسی‌های مطمئن، `TRUSTED_PROXY_HOPS`، پیش‌فرض ۱)، نه از اولش که خودِ کلاینت می‌فرستد |
| داده‌ی تمیز | سرور همان `sanitizeSave` بازی را اجرا می‌کند (`src/game/sim/sanitize.ts`). عددِ بی‌معنا سالم می‌شود و کلیدِ ناشناخته دور ریخته می‌شود. سیوِ نامعتبر `422` است |
| ردیف‌های قدیمی | ردیف‌های پیش از P5.13 مالک ندارند و اولین نوشتنِ معتبر قفلشان می‌کند |
| کلاینتِ صادق | ردِ قطعی (`401`، `403`، `413`، `422`) یعنی «فقط محلی» و در صف تکرار نمی‌شود. `429`، `5xx` و خطای شبکه در صف می‌مانند تا بعداً ارسال شوند |

شاهد: `tests/save-api.test.ts` هندلرِ واقعی را با انبارِ حافظه‌ای تست می‌کند. `tests/save-pg.test.ts` همین قاعده‌ها را روی Postgresِ واقعی اجرا می‌کند؛ CI برایش یک سرویسِ Postgres 17 بالا می‌آورد.

## کیفیت

```bash
npm run typecheck      # TypeScript — باید صفر خطا باشد
npm run lint           # ESLint
npm run test           # تست‌های منطق بازی (Vitest)
npm run check-assets   # بررسی وجود همه‌ی تصاویر/فونت‌های ارجاع‌شده
npm run verify         # همه‌ی موارد بالا + build
npm run roadmap        # بازتولید ROADMAP.md از docs/roadmap.json
```

## ساختار

```
src/
  app/            مسیرهای Next.js و API (health, save)
  game/           موتور بازی
    data.ts       تعریف محصولات، ساختمان‌ها، تحقیق‌ها، مهارت‌ها، دستاوردها
    logic.ts      شبیه‌سازی اقتصاد و قواعد (headless و تست‌پذیر)
    render.ts     دروازه‌ی موتور رندر ایزومتریک روی Canvas 2D
    render/       زمین در بومِ کش (ground)، اسپرایتِ درخت و محصول (nature)، ساختمان‌ها، یک فریم (scene)
    story.ts      متن ۱۱ فصل داستان
    lineageStory.ts  فصل‌های نسل: قالب‌ها + متغیرهای نسلِ قبل (نام، سبک، عددها)
    Story.tsx     سیستم نمایش سینمایی (صحنه‌ی مشترک در StoryStage.tsx؛ پرده‌ی نسل‌ها در LineageStory.tsx)
    Game.tsx      ریشه‌ی بازی (فقط ترکیب ماژول‌ها، < ۲۰۰ خط)
    store.ts      وضعیت بیرون از React + useGame (useSyncExternalStore)
    loop.ts       حلقه‌ی ۶۰ فریم + سازگارسازی خودکار رزولوشن (با سقفِ پسماند)
    icons.tsx, art/  آیکون‌ها و چهره‌های SVGِ دست‌ساز برای React و بوم
    usePersistence.ts  بارگذاری/ذخیره‌ی آفلاین‌فِرست، پشتیبان چرخشی، گزارش غیاب
    useCanvasInput.ts  ضربه، کشیدن، زوم دوانگشتی، نگه‌داشتن = ۳×۳
    persist.ts, net.ts سیو محلی/ابری، صف آفلاین، Service Worker
    ui/           HUD، نوار ابزار، لایه‌ها، شیت پنل‌ها و ۱۲ پنل (هر فایل < ۳۰۰ خط)
  db/             لایه‌ی پایگاه‌داده (lazy، اختیاری)
public/images/    تصاویر داستان، لوگو، آسمان
docs/             مستندات پروژه و نقشه‌ی راه
tools/            اسکریپت‌های کیفیت و تولید مستندات
tests/            تست‌های خودکار
```
